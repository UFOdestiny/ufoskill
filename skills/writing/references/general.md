**全文主线：具体问题 → 现有解释或做法留下的缺口 → 核心洞察 → 由洞察导出的设计 → 关键证据 → 新的认识或能力。** 章节内部的因果与依赖关系优先于套句、模块数量和形式上的整齐。

**1. 故事、novelty 与 insight**

- 先用一句话说清“本文发现了什么，因此能怎样解决什么问题”。全篇围绕这一中心判断展开；Abstract 压缩它，Introduction 建立理由，Method 实现它，Experiments 检验它，Conclusion 提炼它。
- **Novelty 是具体差别及其意义：** 相比最接近的工作，改变了哪项问题设定、信息需求、机制、性质或解释，因此新增什么能力。仅更换名称、拼接组件或提升一个分数，不足以解释新意；用具体比较让读者看见贡献。
- **Insight 是设计背后的认识：** 哪个观察、关系或结构解释了困难，并使某个设计成为合理选择。先讲认识，再讲操作；“我们提出一种新框架”只是贡献声明。观察可以来自数据、例子或理论，不强制另做动机实验。
- 挑战、设计与验证相互对应即可，不机械凑成三组。分析论文围绕研究问题与发现组织，理论论文围绕对象、性质与推论组织，数据集论文围绕能力缺口、构建原则与验证组织。

**2. 章节顺序与篇幅**

默认：**Abstract → Introduction → Problem Formulation → Method → Experiments → Related Work → Conclusion → Limitations（可选）→ Ethical Considerations（可选）→ Appendix**。参考文献按模板放置；已有章节标题可保留其对应职责。下表是经验型方法论文的起始预算，按正文占用空间估算，含归属各节的图表，不含参考文献、附录及单独计页的可选章节。

| 章节 | 起始占比 | 篇幅主要用于 |
|---|---:|---|
| Abstract | 3% | 一条完整贡献链，通常 150–250 英文词 |
| Introduction | 16% | 问题、缺口、洞察与贡献，通常 6–8 段 |
| Problem Formulation | 8% | 输入输出、可用信息与目标，通常 2–4 段 |
| Method | 28% | 核心机制、设计理由与完整使用流程 |
| Experiments | 36% | 主效果、设计验证及有价值的进一步发现 |
| Related Work | 6% | 最接近路线的定位，通常 2–3 个主题段 |
| Conclusion | 3% | 核心认识与成果，通常 1 段 |

占比合计 100%，是编辑起点，不是文献统计或会议规定。短摘要服从目标字数；理论贡献突出时增加 Method 中的分析，发现型论文增加 Experiments，数据集论文将 Method 用于构建与验证设计。优先压缩重复背景、次要变体和报数，再将长证明、配置与完整分项结果移入附录；保住解释核心设计和核心发现的空间。不要用小字号和挤间距替代内容取舍。

**3. 数字密度与信息分层**

摘要通常留 2–3 个关键结果数值；引言留 1–2 组比较；实验每个结果段留 1–2 组能说明发现的比较；结论通常不报数，必要时保留一组。数字数量是可读性参考，不必凑满。正文说趋势、差别与意义，图表给完整值，附录给完整设置及扩展结果。方法中的公式参数和定义常数不按“结果数字”计数。比较须说清对象、指标与关键条件，区分百分点、相对提升和绝对差值。

**4. 正文可读性与理论密度**

- 每节先回答一个读者问题，每段推进一个中心判断。段首给判断或目的，随后解释或举证，段末交代其作用或自然引出下一步；不要求每段都补总结句。
- 首次阅读应能沿着文字读通“为什么、做什么、得到什么”。先给直觉、例子或总览，再引入必要符号；使用领域通用术语，同一对象保持同一名称，避免给普通操作层层命名。
- **保留理论骨架，压缩推导负担。** 正文保留定义方法的公式、核心性质及条件，并解释它为何改变设计或结论。长证明、辅助引理、代数展开放附录。经验型论文不为显得严谨堆定理；理论型论文保留核心证明思路，不照搬经验论文的低理论密度。
- 连续出现定义、公式、定理时，检查读者是否知道每一步的用途；需要解释就插入解释，关系简单就并入行内。没有统一的每页公式上限。图与算法用于缩短理解路径，不能替代关键机制的文字说明。

**5. 直接、有取舍的写作**

直接写发现、操作和收益。删去无信息的自我辩护、反复让步、预演审稿人质疑和“虽然简单／有限，但仍然……”式开场。与主线无关的不利讨论、失败尝试、重复限制及泛泛风险可以删除；有解释价值的补充材料按需移入附录，不要求每项结果后附弱点。

保留会改变结论含义的事实与条件，并自然融入对应陈述；删掉弱结果后若“所有任务均改善”已不成立，就改写这个主张。数值、实验、引用与定理条件沿用证据。`show` 用于直接发现，`suggest` 用于解释性推断，不靠层层 `may / potentially / to some extent` 表达严谨，也不以夸大的确定性替代证据。

Abstract、Introduction、Conclusion 使用对应文件中的衔接框架；其余章节只建议语义合适的连接，不规定连接词配额。写完检查信息是否前进，删除同一贡献在相邻段落中的重复铺陈。
