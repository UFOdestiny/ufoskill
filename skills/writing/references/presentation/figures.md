# 图

**三类图各承担一个任务：Teaser 建立问题与洞察，Framework 解释计算流程，Experimental Results 用证据检验贡献。** 本文件管图的内容、面板与图注；字体、线条、坐标与配色见[绘图规格](figure-drawing.md)，正文如何引用图见[交叉引用](../style/cross-references.md)。

| 维度 | Teaser | Framework | Experimental Results |
|---|---|---|---|
| 核心问题 | 为什么值得研究，关键洞察是什么？ | 输入如何经过关键操作得到输出？ | 新机制是否有效，有哪些收益？ |
| 放置位置 | Introduction，靠近首次讨论 | Method，靠近总领段 | Experiments，靠近对应分析 |
| 内容顺序 | 问题 → 解决机制 → 代表效果 | 输入／表示 → 关键运算 → 输出；另示训练与可选分支 | 按实验顺序：总体比较 → 消融 → 机制验证 → 进一步分析 |
| 面板结构 | 默认全宽横排三个 subfigure (a)(b)(c) | 按实际计算关系组织，优先用少量面板 | 默认全宽横排三个 subfigure (a)(b)(c) |
| 主要文字 | 少量必要标签 | 精确模块名、必要符号与连接 | 坐标、单位、图例及统计说明 |

面板数按论文实际内容调整；用户指定面板数、版式或栏宽时按用户要求，投稿模板有明确要求时以模板为准。

## 共同要求

- **位置与图注：** 图靠近首次引用，主图注置于图下并与图同页。
- **图注精简有力：** 首句概括整图信息，每个子图最多两句，交代内容或发现；不罗列可在正文或表格查到的细节。Teaser 与结果图内部不放标题，编号及短名称放各自 subfigure caption。
- **不重复图中已有的信息：** 坐标轴、图例或子图标题已写明的指标、系列和单位，图注不再复述；默认的汇总范围按[数字](../style/numbers.md)不写。括号只留读者从图中得不到的对应关系，如图例简称所指的方法。
- **标签与对象一一对应：** 每个对象只用一个标签，不写 `X, e.g. Y` 式的双重标注；坐标名写清计量的是什么。图中术语必须在图注或正文中有明确含义。
- **区分示意与证据：** 数值、样本和结果曲线必须来自可追溯数据。带坐标或数值、可能被当成测量结果的示意，在图注中注明为示意；一看即知的示意图不再标注 `schematic`。直接使用或改编他人图形时注明来源。
- **图文一致：** 图中数值、正文结论和表格口径一致（见[数字](../style/numbers.md)）。

## Teaser：问题 → 解决机制 → 效果

- **布局：** 放在 Introduction。从左到右形成同一条论证，各面板共享必要的对象、模型、颜色或例子，不放三个互不相关的小结果。Teaser 在原位置就能读懂，不出现引言没有解释的概念。
- **(a) 问题：** 展示具体问题、关键矛盾或现有方法的不足，让读者看到已有方法为什么遇到困难。真实案例或统计图交代来源与条件。
- **(b) 机制：** 突出本文改变问题的一步，展示关键观察、信息来源或操作如何作用于 (a) 的困难。保留理解洞察所需的最小结构；完整训练流程、全部模块和损失留给 Framework。
- **(c) 效果：** 从已有结果中选择一个直接支持核心贡献的代表性比较，如相同预算下的质量提升、相同质量下的成本下降，或机制改变前后的行为差异。只放引言已解释过的方法与基线，不放需要额外说明的变体；注明比较对象、指标方向和关键设置，完整结果在实验章节展开。
- **图注：** 首句概括整图，随后按实际面板编号说明问题、机制与证据；采用默认三面板时分别对应 (a)、(b)、(c)。简要介绍即可，只保留理解核心贡献需要的信息；补充名单、实现细节和完整设置留给正文与附录。示意与测量的区分见上文“区分示意与证据”。

## Framework：准确呈现计算关系

- **对应方法内容：** 根据方法、公式或算法绘制模块、符号和箭头，如 $s_k$ 参与训练损失，就放在相应训练分支。核心贡献模块占据足够空间，通用背景模块适当压缩。
- **主路径能顺着箭头读通：** 明确输入、表示、关键运算与输出；箭头代表实际数据或依赖关系。监督信号、参数更新和推理数据流有区别时，用线型或分组区分，并在图注解释。
- **训练、推理和可选分支分清：** 推理主路径用实线；可选部分用虚线框和虚线箭头；仅训练部分放入虚线大框。二者同时出现时，用不同虚线节奏或层级区分，并在图注统一说明，不在每条线上附加解释文字。
- **与 Method 一一对应：** 每个模块的标题与 Method 中对应小节的标题一致，并在标题后用括号标注小节，如 `Alignment (§3.1)`；模块内的行、框名称与小节内的段落名称一致。不在图中呈现的步骤（如训练完成后的迁移或部署），空间允许时在图中对应位置加标记，否则在图注中说明对应小节。箭头连了什么，图注就描述什么。
- **同一对象保持同一画法：** 同一组 token 在不同位置保持数量、顺序、配色和形状一致；表示改变时，用明确运算及标签体现。示意置信度条用长度表达关系，实例标注对应结果数值。保留必要运算符，不加入装饰性符号。

## Experimental Results：按实验顺序选取证据

- **布局：** 放在 Experiments，每个面板回答一个主要问题。按总体比较 → 消融 → 机制验证 → 进一步分析的顺序排列实际选用的证据；默认三个面板，消融与机制验证可共用一个面板，需要分别展示时可拆开。优先从已有实验中选择互补证据，不放三张同义的“我们更好”图。
- **总体比较：** 与相关且有竞争力的基线比较，交代数据集、模型、指标、评价协议和影响解释的预算条件；沿用相同划分和统计口径，文献报告值与自行复现值标明来源。
- **消融与机制验证：** 清楚标注完整方法与去除／替换关键部分的版本，先呈现删除／替换后的变化；再用中间量或控制实验说明新机制是否产生预期作用，不把性能下降本身当作机制解释。
- **进一步分析：** 按论文主张选择效率—质量权衡、跨域泛化、规模变化、鲁棒性或应用效果，展示与整体表现互补的发现。
- **图注：** 先概括观察到的发现，再交代面板、指标与必要设置，解释误差带和显著性标记。
