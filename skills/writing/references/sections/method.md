# Method

**组织链：总领段 → 按依赖展开的关键机制 → 学习或求解 → 推断与使用。**

## 总领段

Method 第一段必须总领整个方法，参考 4–5 句，按以下顺序：

1. 承接任务目标，说明关键洞察如何改变求解方式。
2. 引用总览图，说明方法由哪几个模块组成：写 `consists of [N] modules`，不写 `in [N] steps`；模块名与总览图一致。
3. 逐个模块：模块名后用括号标出对应小节，用一句说出该模块实际做什么、解决引言中的哪个挑战，如 `Granularity alignment (Section~\ref{sec:align}) splits each document into query-sized passages, removing the mismatch that causes most retrieval errors.`
4. 用一句交代各模块如何串成主流程、最终输出什么（可与最后一个模块合句）。
5. 有理论小节时，用一句指向，写 `A theoretical analysis (Section~X) explains ...` 或 `We analyze ... in Section~X`。

## 模块名与小节

- **模块名贯穿全文：** Introduction 第 4 段列出的关键设计、Method 总领段、小节标题与总览图必须使用同一组模块名，并在后文反复使用这些关键词。关键模块与引言中的挑战一一对应（模块 A 解决挑战 1，模块 B 解决挑战 2）；分类器等标准组件不作为 novelty 陈述。
- **小节与总览图一一对应：** 小节标题、段落标题与关键名词和总览图中对应模块的名称一致；小节按实际计算或论证关系命名。图中的小节标记规则见[图](../presentation/figures.md)。
- **训练后的操作：** 描述训练完成后操作（如迁移、部署）的小节，首句点明这一点，如 `Once ... is trained, we ...`。

## 段落结构

| 内容块 | 内部逻辑 | 参考占比 |
|---|---|---:|
| 总领段 | 见上文总领段的顺序 | 15% |
| 核心机制 | 本步要解决什么 → 用已有对象如何计算 → 结果为何有用、交给哪一步 | 50% |
| 学习／求解 | 哪些量未知 → 用什么信号与目标估计 → 如何得到最终参数或解 | 20% |
| 推断／使用 | 新输入经过哪些操作 → 得到什么预测或决策 → 必要资源代价 | 15% |

**每个机制的展开：目的与直觉 → 数学或算法定义 → 作用与衔接。** 先说明为什么需要这一步，再给实现；用上一小节已得到的对象解释下一步，不反复重新介绍任务。标准组件简述并引用，主要篇幅给真正新增的机制。公式写法见[公式与理论](../style/math.md)。

## 要求

- **依赖顺序优先：** 先表示再聚合，先定义量再使用量，先目标再求解。介绍多个组件后，用一段、公式或算法把它们合成完整方法，不留给读者自行拼装。没有训练的算法省去学习块，分析型工作展开分析程序，数据集工作展开构建流程。
- **设计理由就近：** 在读者可能问“为什么这样做”处，解释设计所利用的结构、信息或性质。少量动机结果可以辅助说明；完整性能比较、消融和实测效率放 Experiments，不在每个设计后列一段防御性讨论。
- **设计与分析分开：** 各模块小节构成完整设计。属于设计的组件（如迁移时使用的特征变换）与推断流程写进它所属的模块小节，作为该小节末尾的一个段落。理论分析单独成块，标题写成分析名（如 `Theoretical Analysis of ...`、`Error Decomposition by Granularity`），不用 `Transfer to a New Domain` 这类操作名；开头直接进入要分析的问题（如 `We now analyze when ...`），不在其中定义新组件或推断流程。
- **理论的位置：** 理论为已提出的设计提供依据时，放在模块小节之后作为最后一小节；理论推出设计所遵循的规则时，可放在 Method 之前单列一节，Method 再说明各模块如何实现这些规则。核心性质按“要说明什么 → 条件与结论 → 对方法意味着什么”展开。
- **流程闭合：** 写清哪些量训练、哪些固定，监督或校准信号从哪里来，推断能访问什么，默认方案如何运行；可选变体放主方案之后。核心算法只靠正文应可理解，工程参数与复现细节可查附录。
- **图文分工：** 总览图展示真实数据流，正文解释关键改变及其作用，算法框整理顺序与分支。三者名称和符号一致，不重复维护三套等价解释；图与算法不能替代关键机制的文字说明。

## 衔接

可选：`To ... , we ...` 说明目的，`Given ...` 承接输入，`This allows ...` 说明作用，`At inference time ...` 切换阶段。读通依赖比连接词丰富更重要。
